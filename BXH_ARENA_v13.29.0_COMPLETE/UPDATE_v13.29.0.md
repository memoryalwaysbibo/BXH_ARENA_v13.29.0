# BXH ARENA v13.29.0 更新說明

## 本版完成

- 稱號與每日簽到採共同任務底層，但資料與開關彼此獨立。
- 玩家中心首頁新增每日主動簽到卡片。
- 會員資料新增「我的稱號／稱號圖鑑／裝備／隱藏／顯示格式」。
- 支援本名、遊戲 ID 與稱號四種組合預覽。
- 最高管理員帳號管理新增功能開關、第一批稱號初始化、人工授予與撤銷。
- 新增 15 個原始賽事稱號及 4 個簽到稱號定義。
- 資料不足的 16 強、8 強、連勝、不敗、跨場地及賽季類稱號預設停用。
- 正式積分結算新增 wins／losses 可信欄位，供未來連勝與不敗條件使用。
- 每日簽到固定使用 Asia/Taipei 伺服器日期，同日只能建立一次。
- 稱號發放使用固定玩家／稱號路徑與 Transaction，避免重複取得。
- 測試帳號的簽到會標記 `isTestData`，不會觸發正式稱號。
- Cloud Functions 載入失敗時只停用新功能，不影響原有 Auth 與 Firestore。

## 保留不變

- 登入與 Session 對帳
- Gmail 簡化帳號輸入
- 玩家報名與賽事報到
- 人員編排與裁判分桌
- 計分、晉級、天梯與賽事封存
- 分享中心與 QR 掃描
- 完成賽事唯讀
- 測試帳號七日資料隔離

## 上線方式

本版本必須部署三個部分：

1. `firestore_v13.29.0.rules`
2. `functions/`
3. `index.html`

Functions 未部署前，請不要開啟稱號或每日簽到功能。正式部署需要 Firebase Blaze 方案，建議先設定預算警示。

## 建議封測順序

1. 先部署 Rules 與 Functions。
2. 最高管理員建立第一批稱號。
3. 只開啟稱號介面與每日簽到，不開自動發放。
4. 使用一個 player 及一個 tester 測試簽到。
5. 人工授予玩家「開拓者」，確認裝備、隱藏及四種顯示格式。
6. 確認 tester 紀錄標示為測試資料。
7. 完成一場正式積分測試賽，確認既有天梯與封存不受影響。
8. 通過後再開啟自動稱號判定及簽到類稱號。

## 尚未宣稱完成

- 舊賽事歷史補算尚未啟用。
- 開拓者前100名正式配額尚未啟用，需先確定正式開放時間及舊帳號排序。
- 16強、8強、連勝、不敗、四方征戰及賽季王者仍維持停用。
- 稱號尚未全面顯示到所有公開對戰畫面；本版先完成會員資料內的選用與預覽。
- Firestore Rules 尚需在可下載 Emulator 的環境執行一次正式規則測試。
